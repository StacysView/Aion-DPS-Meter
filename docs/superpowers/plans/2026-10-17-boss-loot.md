# Field bosses, world loot, quiet updates - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** field boss respawn timers (footer, window, reminder), a local "loot picked up" window, and a quiet "update waits for the next start" line.

**Architecture:** two static stores fed passively by the frame decoder (`Aion2FieldBosses`, adapted from Skeeve; `Aion2Loot`, new), persisted under `%AppData%\Aion DPS Meter` only once the GUI enables it; small pure helpers (`FieldBossTimers`) for the footer and reminders; two WPF windows in the "modern classic" look of `FightHistoryWindow`.

**Tech Stack:** C# / .NET 10 WPF, Velopack 1.2.0, selftest (`dotnet "Aion DPS.dll" selftest`).

**Spec:** `docs/superpowers/specs/2026-10-17-boss-loot-design.md`

## Global Constraints

- Work only in `C:\dev\Aion-wt-boss` (branch `feat/boss-loot`). Build: `dotnet build Client -c Release`. No version bump, no tag, no push.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never launch the app without arguments (UAC). Tests: `cd Client\bin\Release\net10.0-windows` then `dotnet "Aion DPS.dll" selftest` -> last line `ALL CHECKS PASSED`.
- Fixtures are hex frames only (from the spec / this plan); never commit a capture.
- No outbound network call of any kind (only the existing update check).
- To limit merge conflicts with the parallel `feat/pets` branch: do NOT edit `Aion2Protocol.cs`'s `OpcodeFamily` enum or `opcodes.json`; new selftests go in a new file `Client/Combat/SelfCheckBossLoot.cs`, called by one line in `SelfCheck.cs` after `SelfCheckHistory.Run()`.
- UI strings in `Client/assets/i18n/ui_strings.json` with at least `en` and `fr` (others may copy `en`). French texts for Stacy, simple words.
- Selftests must never write to `%AppData%`: persistence only after `EnablePersistence()`, called by `MainWindow` only.

## Review Focus

- A 0x0191 frame of an instance map (600xxx, count 0 or out-of-range places) must not change any state - test in Task 1.
- A frame cut short (truncated list) must be rejected, not half applied - test in Task 1.
- Another player's loot picked by him (0x1F56 with last byte 00 but no inventory add) must not be counted - test in Task 4.
- A watched boss whose state is unknown shows `Gartua ?`, never a wrong countdown; a respawn time in the past shows "here" - test in Task 2.
- A broken/missing `aion2-loot.json` or `aion2-fieldbosses.json` must start empty, not crash - test in Task 4 (loot) and covered by Skeeve's try/catch (bosses).

- Rules (spec): 0x2136 -> current zone (u32 at 6, ignore 0); 0x1E56 (len >= 47) -> remember drop id (bytes 3-6) -> (item u32 at 39, count u32 at 43), max 500 kept; 0x1B56 (len >= 25, byte 3 in {0,1}) -> remember (item id at 13, time); 0x1F56 (len >= 19, last byte 0) for a remembered drop with an inventory add of the same item within 1.5 s before -> one pickup (count of the drop) in the current session/zone; a new session when the last pickup is more than 30 min old or none since `EnablePersistence`/reset; same item in the same map of a session merges (counts added, `At` = latest).
